# Vibe Design：现状判断与整体产品方案

版本：2026-09-11 · 待验证的产品方案

**建议定位：帮助使用 AI 编程的人，为自己的网页选对视觉方向，并把这个方向可靠地交给 AI 执行。**

当前项目已经有可用的内容和交付基础。下一步最值得投入的是选型依据、项目适配和结果验证。衡量产品价值应看用户是否完成了满意的网页改造。

本方案基于当前仓库、线上首页、风格详情和对比页，以及 390×844 手机详情页抽查。未进行全部 30 个演示的逐页设计评审，未重新执行仓库完整测试，也没有访问量、真实用户访谈或付费数据。因此，下文区分已观察到的事实、产品判断和待验证假设；排期为资源假设下的建议，不是已承诺计划。

## 1. 现状哪里好，哪里不好

### 已经做对的部分

| 做得好的地方 | 当前证据 | 产品价值与保留方式 |
| --- | --- | --- |
| 价值表达直接 | 首页明确告诉用户看效果、复制提示词、交给自己的 AI 工具 | 用户能理解下一步；保持短路径和无需登录的首次体验 |
| 可以验证的真实演示 | 卡片来自演示缩略图，详情有可交互页面、设备视口、源码和独立打开 | 用户能看布局和交互，降低仅凭风格名称想象效果的成本 |
| 交付素材较完整 | 提示词、从实际源码提取的 CSS 变量、带素材与字体的独立 HTML、Skill | 这些资产可以直接支持改造，比只给风格描述更有用 |
| 已开始区分原则与具体示例 | 数据包含设计语言、流派、布局、材质等类型；说明构图、关键手法、误用与部分参考来源 | 防止把某组配色误当成整个风格；继续补齐证据与适用边界 |
| 基础体验有连续打磨 | 统一控件、设备切换、双语、主题、对比、复制失败后的下载出口 | 保留已形成的交互一致性，后续围绕主路径调整 |
| 内容维护有工程基础 | 数据生成 Skill；仓库有源码与缩略图指纹、视觉检查脚本和 CI 配置 | 有条件把“预览和导出一致”变成稳定的质量承诺；脚本存在本身不代表本次检查已通过 |

### 主要问题，按对用户结果的影响排序

**第一，选型功能提供了候选，没有充分帮助用户做判断。**

首页支持场景、纯 CSS 实现难度、风格标签和名称搜索，但不知道用户做的是官网还是工作台、信息密度多高、希望访客做什么、已有何种品牌约束。场景数据是固定列表，也没有逐项解释推荐条件。例如“SaaS / 科技产品”并未区分营销首页与高密度管理界面。

这会带来一种可能的失败：用户选中了吸引自己的演示，却不一定选中了适合业务的方向。需要通过真实任务观察验证发生频率。

**第二，产品承诺与默认交付模式有偏差。**

首页承诺改造用户已有网页；详情默认选择“复现当前演示”，卡片的“完整提示词”也调用复现参考生成器。虽然生成文本包含保留业务逻辑的要求，但“尽量保留演示参数”和“适配已有业务”仍需要用户与下游 AI 自行协调。

卡片用“快捷 / 完整”区分，详情用“复现 / 应用”区分，实际上混合了长度和任务类型两个维度。建议先统一用户任务，再决定输出长度。

**第三，对比有观看价值，决策支持不足。**

当前详情的对比入口自动选择列表中的下一个风格，缺少推荐理由。线上抽查的新粗野主义与双色调演示，业务、文案、图片、构图都不同。即使视口一致、同步滚动，用户仍难判断自己喜欢的是风格还是示例内容。

保留原创作品对比，同时为少量重点候选增加“同一业务内容的不同演绎”。不必立即让 30 种风格套用同一个模板。

**第四，关键判断信息的优先级偏低。**

详情先展示提示词，适用场景与取舍则位于说明区域后部的折叠内容。桌面 1280 像素宽度抽查中，左侧风格目录与右侧说明挤占画布，演示显示为 55% 缩放；适合总览，但判断文字与材质需额外全屏。手机抽查中，首屏主要由演示占据，核心带走操作需要继续寻找。

建议把适用条件和主操作前移，保留完整阅读和全屏能力。仅靠进一步增加图标、动效或说明文字，难以解决这个顺序问题。

**第五，浏览结束以后缺少可观察的结果。**

当前应用状态保存主题、语言和预览设置；未在已检查的业务代码中发现候选清单、项目简报或改造结果反馈路径。没有证据说明用户复制后是否执行、效果是否满意、哪里经常失败。站外执行天然难观测，因此需要自愿反馈与真实任务抽样，不能把复制量直接当成改造成功量。

**第六，分类和内容质量仍有改进空间。**

类型数据已经区分设计语言、布局、材质和动态表现，但浏览时仍以同一层级平铺。“热门”和“流行”未展示统计口径或时间范围，容易被理解成实时热度。参考依据当前仅部分风格具备。建议采用稳定、可解释的筛选标签，并逐步补齐重点条目的来源和限制。

另有一个已从源码确认的交付问题：提示词生成器默认公共域名，但卡片和详情显式传入 `window.location.origin`，所以本地或临时预览环境会导出对应环境的链接。需要统一成可配置的公共参考源，并保留离线附件兜底。

## 2. 用户、价值与产品路线

### 优先服务谁

第一阶段优先服务：**已有网页或原型、使用 AI 编程、缺少视觉选型方法的独立开发者和小团队产品负责人。** 首批验证任务聚焦 SaaS 营销页与个人作品集；这是用于降低供给复杂度的建议范围，后续根据任务表现调整。

他们的触发场景是“网页已经能用，但视觉普通、风格不统一，或说不清该怎么改”。当前可选择自行浏览参考、直接向 AI 描述、找模板或委托设计。Vibe Design 要减少的成本是选型犹豫、提示词反复补充和生成后的返工。

| 参与者 | 提供什么 | 得到什么／承担什么 |
| --- | --- | --- |
| 网页创建者，也是早期主要决策者 | 页面目标、约束、候选选择；自愿提供结果反馈 | 可解释的视觉方向和可执行改造简报；决定是否采用与发布 |
| Vibe Design 内容维护者 | 风格原则、演示、场景适配说明、参考包版本、质量复核 | 获得使用和失败证据，持续改进内容；承担维护成本 |
| 用户自己的 AI 编程工具 | 读取项目、实现代码、执行检查 | 消费结构化简报；实际执行能力依工具环境而异 |
| 小团队设计／业务负责人 | 确认品牌要求与业务完整性 | 审核候选与结果；目前不需要单独建设审批系统 |

现阶段没有付费证据，不能默认使用者就是愿意付费的客户。

### 三条可选路线与选择

| 路线 | 主要收益 | 所需投入与代价 | 当前判断 |
| --- | --- | --- | --- |
| 扩大设计灵感图库 | 更多可浏览内容与搜索入口 | 持续搜集、编辑和分发；结果仍依赖用户自行转译 | 可作为内容补充，不作为下一阶段主投入 |
| 选型、适配、导出的轻量工具 | 接近现有用户任务，可复用演示、提示词和 Skill | 需要场景规则、项目简报和真实任务验证 | **推荐主路线** |
| 站内 AI 建站与在线编辑器 | 能直接承接生成和修改 | 增加模型、执行环境、项目托管及故障恢复成本；目前资源未明确 | 暂缓，先验证选型与交付的价值 |

外部产品说明也支持这种功能边界的区分：Curated 按行业和风格组织真实网站参考；Realtime Colors 让用户在真实页面结构中检查配色与字体，并导出配置。这是对已存在机制的观察，不足以证明 Vibe Design 的需求规模。[Curated](https://curated.design/)；[Realtime Colors](https://www.realtimecolors.com/)

推荐路线的判断依据是现有资产与新增成本的匹配。若真实用户普遍已经会选风格、主要困难集中在执行代码，应该把资源转向 Skill 的交付质量；若用户只想浏览案例且缺少改造需求，则应保留轻量参考站定位，不继续扩大工作流。

## 3. 核心流程：让每一步都有可用输出

主路径：**带着页面目标进入 → 缩小候选 → 理解取舍 → 确认改造范围 → 导出给 AI → 核对实际结果。**

| 阶段 | 输入与产品工作 | 给谁的输出 | 完成信号与失败恢复 |
| --- | --- | --- | --- |
| 明确任务 | 用户选择页面类型、视觉目标，选填品牌与不可改内容 | 推荐逻辑获得足够约束 | 输入不足仍可浏览；不强制填写长问卷 |
| 选型 | 维护者编写的适配规则筛选并解释候选 | 用户获得最多 3 个方向，以及各自的收益与代价 | 能说明选择原因；无明显匹配时说明限制并放宽条件 |
| 比较 | 用户选 2 个候选，检查同视口演示和关键差异 | 用户确认一个方向或返回调整目标 | 不默认以数组顺序配对；候选不适合时可撤回 |
| 适配 | 用户确认目标页面／组件、保留项、风格表达强度 | AI 获得可编辑改造简报 | 未指定范围时，简报要求 AI 先识别并确认范围 |
| 交接 | 系统组合约束、原则、参考、验证要求 | 用户复制 Markdown 或下载参考包，交给自己的工具 | 复制失败可下载；参考打不开可用 HTML 附件 |
| 验证 | 用户与 AI 按简报检查，选填“不够像／影响可用性”等问题 | 用户获得针对当前结果的修正提示词 | 成功可保存选择；失败保留原目标与约束，继续修正 |

项目输入首版保存在本机，允许清除。分享候选时只分享公开风格 ID；包含业务简报的链接或文件需要明确显示将带走的内容。反馈首版可以是轻量人工收集，不需要先建设账户和云端项目系统。

## 4. 页面与功能方案

### 首页：理解用途并开始选择

保留 Vibe Design 的大字标、克制的橙色、真实精选作品，缩短品牌展示与实际选型之间的距离。

建议首屏文案：

> 给你的网页，选一个合适的样子。
>
> 看真实效果，比较适用场景，把改造说明交给你正在使用的 AI。
>
> 主操作：为我的网页选风格　次操作：浏览全部风格

已知想要哪种风格的用户可直接搜索；不知道名字的用户进入轻量选型。Skill 保留导航入口，并在导出完成后提示适合重复使用的人安装。

### 风格库：服务筛选与候选积累

首要筛选维度为页面用途、信息密度、视觉倾向；纯 CSS 实现难度作为辅助信息。保留风格名称搜索，补充场景词和常用别名。移除无依据的热度暗示。

卡片展示真实预览、名称、适用情况、一句主要取舍。保留快速导出，但使用统一任务名称。增加本地候选清单，最多收藏 3 个，选其中 2 个对比。筛选条件和浏览位置在返回时恢复；无结果时展示清空与放宽条件。

### 选型结果：给出少量解释充分的选择

输入控制在一屏：页面类型、希望用户完成的动作、视觉倾向；信息密度与保留项可展开。第一版采用可维护的显式规则，不调用模型，不显示没有校准依据的匹配分数。

每个结果回答三件事：“为什么适合你”“需要接受什么代价”“什么情况下不要用”。例如对文字较多的产品介绍页，推荐强调排版层级的方向，并说明强材质效果宜控制在少量区域；这类文案必须对应明确规则与示例。

### 详情页：先确认适合，再带走

桌面保留中央大预览，弱化持续展示 30 项目录的必要性，可切换为候选清单或收起。右侧顺序调整为：适用判断 → 主操作 → 3 条视觉规则 → 展开的完整简报 → 源码、Token 与参考资料。

主操作统一为“用于我的网页”。其下提供两种清楚的意图：

- **改造现有页面**：默认。保留业务与品牌约束，迁移布局和视觉原则。
- **参考这个演示制作**：明确说明如何处理演示文案、素材与实际业务；避免同时发出“严格照搬”和“随意调整”的冲突要求。

手机以“看效果／用这个风格”分区和常驻主操作降低寻找成本，保留独立打开完整演示。详细源码与完整变量按需展开。

### 对比页：解释差异并支持最终选择

优先使用用户候选；没有候选时，请用户选择第二个方向，或给出带理由的相关候选。重点场景提供同一份内容在 2—3 个方向下的演绎，同时保留各自原创示例，避免统一模板抹平风格。

视口与同步滚动沿用现有能力。页面增加适用内容密度、品牌印象、素材依赖、动效与实现代价的对照，并提供“选择 A／选择 B”进入简报。手机提供 A/B 切换，保持相近阅读位置。

### 导出与回访：完成交接，保留修正入口

用户看到“将改哪些页面、保留什么、采用哪些规则”的短摘要，再查看完整文本。输出包含：目标与范围、保留项、风格原则、可调整参数、演示参考及版本、验收要求、已知限制。

默认复制完整可执行简报；下载 Markdown 和 HTML 作为补充。复制成功后说明在现有项目的 AI 对话中使用，并提供结果自检与修正入口。浏览器内自愿反馈只是结果来源之一，应单独记录用户自报与人工观察。

## 5. 内容与实现边界

当前内容数量足以做第一轮验证。先选 6—8 个覆盖不同任务的重点方向，统一补齐适用条件、不适用条件、真实示例和交付质量，再考虑扩大内容。

对重点方向做两类检查：同一风格迁移到不同业务时是否仍成立；同一业务在不同方向下，用户是否能说出差异与选择依据。内容维护者负责审美与适用性复核，自动检查负责链接、素材、布局异常和产物一致性。

在现有 React 静态站上增量实现：

- 扩充场景数据与风格规格，存储适配条件、代价和推荐理由；使用版本字段保持可追踪。
- 为候选、简报和筛选状态增加本地保存；无需首版账户系统。
- 卡片、详情、下载、Skill 共用同一个简报生成逻辑，统一模式名称和公共参考地址。
- 对比复用现有预览组件，仅为经过选择的场景增加同内容示例。
- 保留现有构建、缩略图和演示检查；新增验证集中在规则、导出一致性和真实主路径。

站内不承担用户仓库的执行和托管。AI 工具无法读取参考、缺少截图能力或生成不理想时，应给可行的附件与人工检查方式，不暗示站点可以保证任意工具的生成效果。

## 6. 执行顺序与资源

建议按“1 名主要开发者＋内容／设计复核支持”估计 3—4 周的首轮迭代。实际可投入人数与时间尚未确认，优先用阶段出口管理范围。

| 阶段 | 核心交付 | 责任与所需资源 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 第一阶段：统一主路径，约 3—5 个工作日 | 统一任务模式和 CTA；适用判断前移；公共参考地址；移动主操作；筛选返回恢复 | 开发负责人执行，产品负责人确认默认任务；复用现有资产 | 用户能从浏览完成一次导出；本地与线上导出引用正确；桌面与手机主路径可完成 |
| 第二阶段：验证选型价值，约 1—2 周 | 本地候选、规则推荐、简报编辑、重点场景对比；第一批真实任务记录 | 内容维护者补规则；产品负责人招募使用者；开发负责人实现 | 用户能解释候选差异；与现有体验相比，选择耗时或执行后返工有所改善 |
| 第三阶段：改进交付与决定是否扩大，约 1 周 | 结果反馈、修正提示词、Skill 同步；处理最常见失败 | 复核者观察实际网页；开发与内容维护共同修正 | 找到可重复的成功路径；明确下一轮投资在选型、内容还是执行质量 |

以上均为建议角色分工，具体人选待项目负责人安排。当前可以确认的资源是仓库、演示、提示词生成链路和公开站点；尚缺的是稳定的用户样本、实际使用数据与持续内容复核容量。用户样本可从已有使用者及开发者社群定向招募，首轮无需付费投放。

## 7. 验证、指标与商业化

首轮建议招募 5—8 名符合目标的人，让他们携带真实页面。任务包含选方向、解释取舍、导出、在自己的工具里执行、核对结果。比较现有流程和新流程时使用相近难度任务并轮换顺序；小样本用于发现失败机制，不宣称统计意义上的提升。

重点记录选择耗时、是否需要额外解释、用户补写了哪些约束、生成后返工次数、能否保留业务功能、用户最终是否采用。先建立基线，再决定定量目标。

| 指标 | 能说明什么 | 解释边界 |
| --- | --- | --- |
| 每周确认完成的有效改造数 | 推荐的核心结果指标：用户采用视觉方向、关键业务仍可用，并完成约定的桌面／手机检查 | 区分用户自报与人工观察，不自动从复制推算 |
| 进入详情／选型后成功导出的比例 | 用户是否拿到了可执行输入 | 导出不代表执行成功 |
| 选型时间与决策信心 | 推荐是否减少犹豫 | 更快但选错并不算改善 |
| 执行后的返工与失败类型 | 简报、参考和规则哪里需要修正 | 记录工具环境，避免把所有差异归因于风格 |
| 新项目中的再次使用 | 是否形成可重复价值 | 此类工具使用频率受项目周期影响，不强求日活 |

若做站内事件采集，优先只记录风格、模式、入口和成功／失败等必要事件，不采集用户代码或完整业务简报；站外结果仍采用主动反馈和抽样复核。具体采集工具后续再定。

获客内容以真实改造过程、同内容风格对照、场景选择指南为主。每篇内容链接到对应候选或简报入口，核对进入后的实际使用。Skill 承接复用与开发者分发；下载量不能当成安装成功量或留存量。

首阶段保留公开浏览、基础导出和 Skill。付费假设优先验证多页面一致性参考包、行业任务包或团队品牌规则，因为它们对应可观察的重复工作。先访谈并取得具体试用意愿，再决定是否定价；目前不把赞助、订阅或付费转换写成收入预测。

阶段复盘必须允许收缩：若用户无需选型帮助，就加强直接浏览和交付；若导出频繁但改造失败，就暂停加内容并修正执行包；若用户只浏览且不执行，就重新检查目标人群和使用动机。

## 8. 首版验收与证据索引

首版至少达到：新用户不经口头讲解可选择并导出；卡片、详情、Skill 对同一意图输出一致；对比对象由用户或明确规则选择；项目保留项进入简报；无结果、复制失败和参考不可达均可恢复；桌面和手机实测完成主路径；真实任务结果有记录。
