# 网页改造优化与验收

本轮围绕已有项目的视觉改造：明确任务、解释推荐、同内容比较、按项目约束交付、维护规则，以及记录执行结果。保留原有30个独立演示和设计配方工作台。

## 实现与证据

| 要求 | 当前实现 | 验证方式 |
| --- | --- | --- |
| 明确项目与保留项 | `/project`，六场景、目标、表达强度、范围、品牌色、目标页面、其他约束 | Node 简报与162种推荐组合；浏览器真实输入、保存恢复和无效导入 |
| 少量有理由的推荐 | 明确规则推荐最多三项，包含收益、取舍、避免条件 | 全组合检查真实风格ID和双语说明 |
| 候选比较 | 最多三候选；选择两项对比；筛选条件与候选在返回时保留 | 浏览器候选与URL检查 |
| 同内容场景 | 六风格×官网/后台×中英；真实交互与固定业务内容 | Node内容/脚本一致；48个尺寸和语言浏览器样本 |
| 项目长期规范 | 改造说明、DESIGN、Skill、检查表、原始HTML、Tokens、品牌覆盖与恢复JSON | 30风格×双语，独立Node crypto核对SHA-256；真实ZIP下载和独立解压 |
| 配方一致性 | 预览、brief、DESIGN、HTML、JSON、Tokens与manifest使用相同最终配置 | 全配方双语、独立校验值、下载/离线浏览器检查 |
| 内容可信度 | 删除无依据的热度、转化与性能承诺，保留具体取舍 | 全30风格和生成文档检查 |
| Agent可读 | Markdown索引、每风格文档、长期规范、便携Skill | 本地链接、源码Tokens/Hash、确定性重建、Skill格式检查 |
| 结果追踪 | 当前简报对应的自报采用/返工/检查项，修正说明和JSON下载 | 浏览器录入保存；项目快照/旧数据迁移单元检查 |
| 证据边界 | 当前构建ID匹配才展示记录；无证据或过期时明确说明 | 浏览器正常/缺失/过期记录检查；JSON和截图来自实际测试 |
| 静态入口 | `/compose`、`/project`、`/cases`静态壳 | 构建文件与实际HTTP访问；线上需另行发布验证 |

## 命令与产物

`pnpm test` 检查数据与导出；`pnpm lint`、`pnpm build` 检查代码和生产产物；`pnpm validate:workflow` 检查项目主路径及标准场景，保存 `output/workflow/report.json`、实际ZIP与截图，并在全部通过后写入 `public/validation` 与 `dist/validation`。`pnpm validate:studio` 保留原创预览检查；`pnpm validate:recipes` 检查全部配方与离线工作台。原有 `pnpm visual` 和 `pnpm validate:render` 继续用于原始演示。

构建指纹由生产代码、静态演示、机读文档等稳定产物计算，验证记录和最后打包的安装归档不参与指纹。样本报告同时保存实际原始演示SHA-256。文件校验、浏览器行为与视觉审美各有边界：构建通过只说明构建成功；报告记录的行为只证明该样本与该环境；用户项目仍需自行验收。

工作台与原始预览的报告分别保存在 `output/recipes/report.json` 和 `output/studio/report.json`，记录构建ID、执行状态与时间；成功前复核构建ID没有改变。`output/visual/report.json` 和 `output/render/report.json` 检查的是 `public/demos` 中的独立HTML，逐项记录实际源码SHA-256。核对报告时要同时检查状态、构建或源码身份以及覆盖范围，不能将旧构建的通过记录算作新版本已验收。

同源范围也需区分：对比页的标准样本预览与该页的HTML下载使用同一份渲染结果；项目改造包附带的是所选风格的原始演示。两者共享原始参数来源，构图与业务内容可以不同。用户品牌色在改造包中以单独覆盖文件表达，原始参考不被悄悄改写。

## 首轮真实项目研究

招募5—8名已有网页、使用AI编程的用户，让他们携带真实任务。不要把仓库内虚构产品演示写成用户成功案例。首轮目标是观察失败机制，不能从小样本推断统计提升。

每项任务保留以下记录，用户可用 `/project` 的本地结果下载功能提供自愿反馈：

| 字段 | 记录内容 |
| --- | --- |
| 起点 | 页面类型、技术栈、已有截图与不满意的问题 |
| 目标与约束 | 主要操作、改造范围、品牌/素材/业务保留项 |
| 选择 | 三个候选、最终选择与原因；记录选择耗时 |
| 执行 | 编程工具与版本、实际说明、额外补充和返工次数 |
| 验收 | 桌面/手机截图、功能回归、长文本、组件状态和未验证项 |
| 决定 | 采用/继续修正/放弃，以及具体原因 |

发布案例前由提供者决定是否公开业务信息与截图。先积累可复核的完整过程，再考虑多页面团队规则与技术栈迁移包的付费试用。本次实现没有接入收费、账户、模型执行、云端代码上传或遥测。
